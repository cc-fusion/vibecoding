# Smart Text Editor

## 1. Interface
- Full-screen, multiline monospace text editor.
- No logo, header, or sidebar; a fixed bottom bar displays autocomplete chips.
- A settings button in the top-right opens a partially sized overlay that slightly blurs the editor and bottom bar. Clicking outside closes it and saves changes.
- Keep the editor's text editable and unchanged until the user accepts a completion.

## 2. Autocomplete and keyboard behavior
- The inline completion is always the first bottom-bar candidate.
- **Tab:** accept the selected completion.
- **Left/right arrows:** cycle through alternatives when available instead of normal caret movement.
- **Up/down arrows and Enter:** preserve their normal editor behavior.
- Left at the first candidate and right at the last candidate preserve normal cursor movement.
- Clicking a suggestion chip accepts that suggestion.
- Support targeted text replacement, including replacing characters immediately before the cursor.
- If no completion applies, show nothing.

## 3. Math engine
- Parse standard mathematical expressions, including operators, parentheses, constants, functions, and implicit multiplication where appropriate.
- Use `decimal.js` for arbitrary-precision arithmetic.
- Support radians and degrees, remembering the previous selection and defaulting to radians.
- Round ordinary previews to four significant digits by default, using standard significant-digit rounding.
- Allow constants and progressively typed numbers to continue beyond normal preview precision.
- Use ordinary decimal notation by default. Offer scientific notation as an alternative when \(|x| < 10^{-4}\) or \(|x| > 10^4\).
- Prefer scientific notation exclusively below \(10^{-1000}\) or above \(10^{1000}\), except when continuing long exact constants or progressively typed numbers.
- Truncate long previews with `...`.
- Show `rad` or `deg` on suggestion chips only when angle mode affects the result.

## 4. Unit engine
- Represent units using a coefficient and exponents of the seven SI base units.
- Support unit arithmetic, dimensional analysis, derived units, and conversions.
- Recognize equivalent expressions and simplify to appropriate units, such as `kg·m²/s²` to `J`.
- Suggest readable, context-appropriate units and normalize quantities where sensible, such as `1500 g` to `1.5 kg` or `40oz` to `2.5lbs`.
- Support metric and imperial preferences.
- Offer one metric and one imperial alternative for convertible quantities.
- When converting explicitly, such as `1 km -> mi` or `1 km to mi`, support selecting a unit from a dropdown on the right side of the bottom bar. The dropdown should only appear if a unit is being suggested.
- Allow users to accept a suggested unit inline or switch to another available unit.

## 5. Settings and developer tools
Include settings for:
- Metric/imperial preference.
- Degrees/radians, defaulting to radians.
- Light/dark theme.
- Font size.
- Enable/disable inline suggestions.
- Debugger/developer menu.
  - Debugging/console logs
  - Editing the known units in the unit engine as JSON.

Also provide a degrees/radians quick switch at the rightmost end of the bottom bar.

## 6. Examples and validation
Use the supplied examples as acceptance tests for:
- Whitespace and cursor positioning.
- Inline calculations and contextual autocomplete.
- Angle mode and function evaluation.
- Significant-digit rounding and precision continuation.
- Scientific notation thresholds.
- Unit normalization, conversion, and derived units.
- Editing existing text through completions.

Preserve ordinary editor behavior whenever no suggestion is active.

- Inline completions shown in quotes
- Bar autocompletions shown in backticks. Note that inline autocompletions are the first item in the bar autocompletions ("a" implies "a"`a`)
- A bar completion without an inline completion should not show inline completions (`a` without "a" means do not inline)
- If no quotes or backticks, do not autocomplete
- Cursor shown in |, if not shown, assume cursor is at end of string

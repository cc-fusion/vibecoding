MPM STUDIO · VERSION 1.1

Physics, exposed to JavaScript.

A browser-native MLS-MPM + CPIC simulation runtime. Use JSON for declarative scenes, ES modules for programmable experiments, or trusted inline JavaScript in the playground.

Same solver, better host architecture. The build reuses the supplied WebAssembly solver. The combined implementation adds worker-first execution, a main-thread fallback, JavaScript scene modules, live interaction APIs, custom level sets, and a framework-free playground.

Quick start

Serve this directory over HTTP(S), then load the standalone browser bundle. WebAssembly and workers are not reliably available from file:// URLs.

<div id="simulation" style="height:520px"></div>
<script type="module">
  import * as TaichiMPM from './src/lib/index.js';
  TaichiMPM.create({
    container: '#simulation',
    scene: 'water-wheel-2d',
    autoPlay: true,
    quality: 'medium'
  }).then(sim => {
    window.sim = sim;
    sim.on('error', console.error);
  });
</script>

TaichiMPM.create() resolves to a Simulation instance. Listen for loaded to know when a scene has initialized.

Execution model

The runtime attempts a dedicated Web Worker first. If the browser does not support Worker construction, or the worker crashes before reporting readiness, the same worker runtime is imported into the main thread. The fallback uses a shorter simulation time slice to preserve responsiveness as much as possible.

Application UI (vanilla HTML / JS)
       │
       ▼
Simulation client + interaction events
       │
       ├── Dedicated Web Worker (preferred)
       │
       └── Main-thread runtime (fallback)
                    │
                    ▼
           JavaScript engine host
                    │
                    ▼
             WebAssembly solver
                    │
                    ▼
               WebGL2 renderer

The fallback is functionally compatible, but large simulations can block UI work because physics and the application share a thread. The fallback event identifies this mode.

JSON scenes

JSON scenes are portable data. The schema supports 2D and 3D, materials, particle shapes, rigid shapes, wheels, emitters, boundaries, custom level sets, gravity, and resolution.

const scene = {
  id: 'water-wheel-demo',
  name: 'Water wheel demo',
  dim: 2,
  resolution: 160,
  gravity: [0, -9.81],
  boundaries: { floor: true, walls: true, friction: 0.35 },
  objects: [
    {
      type: 'particles', material: 'water', shape: 'sphere',
      center: [0.35, 0.72], radius: 0.10, density: 4
    },
    {
      type: 'rigid', shape: 'wheel', center: [0.65, 0.30],
      radius: 0.14, blades: 8,
      motion: { enabled: true, speed: 90 }
    },
    {
      type: 'emitter', material: 'water', shape: 'rect',
      center: [0.5, 0.9], size: [0.08, 0.025],
      velocity: [0, -1.4], duration: 5, density: 2
    }
  ]
};
await sim.loadScene(scene, { autoPlay: true });

Particle density controls sampling per cell. massDensity controls physical material density. They are different quantities.

JavaScript scene modules

ES modules are the preferred programmable-scene format. The worker imports the module, so setup() and update() run alongside the solver and retain normal module scope.

// scenes/my-scene.js
export const metadata = {
  id: 'my-scene', name: 'My scene', dim: 2,
  duration: 0, frameDt: 0.01
};

export function setup(ctx) {
  const mpm = ctx.createMPM({
    resolution: 160,
    gravity: [0, -9.81]
  });
  const walls = mpm.create_levelset();
  walls.add_plane([0, 1], -0.06)
       .add_plane([1, 0], -0.06)
       .add_plane([-1, 0], 0.94)
       .set_friction(0.4);
  mpm.set_levelset(walls);

  const water = ctx.tex.sphere([0.5, 0.7, 0.5], 0.1).mul(4);
  mpm.add_particles({
    type: 'water', density: 1000,
    density_tex: water, color: [0.3, 0.6, 1]
  });
  return {
    mpm,
    update(t, dt, api) {
      if (t > 1 && t < 1 + dt) {
        api.addParticles({
          material: 'jelly', shape: 'sphere',
          center: [0.5, 0.9], radius: 0.03
        });
      }
    }
  };
}

// In the host page:
await sim.loadSceneModule('./scenes/my-scene.js', {
  autoPlay: true
});

Module contract

  • metadata (or scene) must declare dim: 2 or dim: 3. It can also include id, name, duration, frameDt, camera, and decor.
  • setup(ctx) must return { mpm }, optionally with update(t, dt, api) or frameUpdate(t, dt, api).
  • ctx exposes engine, tex, quality, MPM, TextureFactory, SegmentMesh, TriangleMesh, LevelSet, createMPM(), addObject(), addParticles(), and createLevelSet().
  • The frame callback receives a small API with engine, mpm, current controls, addParticles(), addRigid(), and emitParticles().
  • An optional onMessage(name, payload, api) export receives forwarded pointer/keyboard input inside the worker. Payloads must be structured-cloneable.

Inline JavaScript & safety

The playground also supports inline source code using the same ES-module contract. This is useful for experiments where creating a separate file is inconvenient.

await sim.loadInlineScene(`
  export const metadata = { name: 'Inline demo', dim: 2 };
  export function setup(ctx) {
    const mpm = ctx.createMPM({ resolution: 128 });
    const field = ctx.tex.sphere([0.5, 0.7, 0.5], 0.1).mul(3);
    mpm.add_particles({ type: 'water', density: 1000, density_tex: field });
    return { mpm };
  }
`);
Inline code is trusted code. It executes with the worker's privileges and is not sandboxed. Do not run source supplied by untrusted users. This implementation loads inline source through a Blob ES module and does not use JavaScript eval() or reconstruct function strings.

External modules are also executable code, not data. Only import scene URLs from origins you trust. Deployments with a restrictive Content Security Policy may need to allow blob: for worker-side inline-module loading.

Real-time interaction

The canvas emits pointer and keyboard events with world-space coordinates. Developers can build custom controls in ordinary HTML, or forward serializable input into a JavaScript scene running beside the solver in the worker.

sim.setInteraction({ enabled: true, mode: 'custom' });
sim.on('pointerdown', ({ position }) => {
  console.log('World position:', position);
});
sim.on('interact', ({ position }) => {
  // Custom behavior; mode 'custom' disables automatic injection.
  sim.emitParticles(position, [0, 0.5], 'water');
});
sim.on('keydown', ({ key, originalEvent }) => {
  if (key === ' ') {
    originalEvent.preventDefault();
    sim.running ? sim.pause() : sim.play();
  }
});

A scene module may export onMessage(name, payload, api). With forwardToScene: true, pointer and keyboard events are forwarded to that callback. It can update scene-owned state and call worker-side methods such as api.addParticles(), api.addRigid(), api.emitParticles(), or api.generalAction(). Payloads must be structured-cloneable. Supported events include pointerdown, pointermove, pointerup, pointercancel, interact, keydown, and keyup. Pointer payloads include the pixel coordinates and a projected world-space position.

Simulation API

play()

Start continuous stepping.

pause()

Stop continuous stepping.

step()

Advance one simulation frame.

reset(options)

Reload the current scene.

loadScene(scene, options)

Load a scene ID or JSON definition.

loadSceneModule(url, options)

Import a JavaScript scene module inside the runtime.

loadInlineScene(source, metadata, options)

Load trusted inline module source.

addParticles(config)

Add particles at runtime.

addRigid(config)

Add a rigid body at runtime.

addWheel(config)

Add a rigid wheel shape.

addEmitter(config)

Add a particle-source emitter.

generalAction(config)

Call a supported low-level solver action.

update(patch)

Change gravity, speed, wheel speed, friction, etc.

setGravity(value)

Convenience wrapper for gravity changes.

emitParticles(position, velocity, material, color)

Inject a small particle source.

send(name, payload)

Forward serializable custom input to a scene module's worker-side onMessage.

setOptions(options)

Update rendering options.

setInteraction(options)

Choose touch, custom, or orbit input mode.

getStats()

Read the latest frame statistics.

snapshot()

Download the current canvas as PNG.

dispose()

Release the worker, renderer and listeners.

Event handlers are registered with sim.on(name, callback). The return value is an unsubscribe function; sim.off(name, callback) is also available.

Emitters, wheels & custom level sets

JSON supports repeat emitters and scripted wheels; JavaScript modules have access to the full level-set builder, rigid meshes and articulation methods.

// Declarative custom collider
const scene = {
  id: 'custom-bounds', name: 'Custom bounds', dim: 2,
  boundaries: { floor: false, walls: false },
  levelset: {
    planes: [{ normal: [0, 1], d: -0.04 }],
    boxes: [{ lower: [0.25, 0.2], upper: [0.75, 0.24], insideOut: false }],
    spheres: [{ center: [0.5, 0.48], radius: 0.12, insideOut: true }],
    friction: 0.5
  },
  objects: [
    { type: 'emitter', material: 'water', shape: 'sphere', center: [0.5, 0.85], radius: 0.025, velocity: [0, -1], duration: 4, density: 2 },
    { type: 'rigid', shape: 'wheel', center: [0.5, 0.32], radius: 0.1, blades: 10, motion: { enabled: true, speed: 120 } }
  ]
};

Custom level-set kinds: planes, boxes, spheres, cylinders, and 2D polygons. Set levelset.includeDefaultBoundaries: true to combine the custom shapes with default floor/wall boundaries.

JavaScript scenes can use mpm.add_articulation() for motor, distance and rotation constraints, and can build custom 2D segment meshes or 3D triangle meshes.

Scope & limitations

  • The project ships the original precompiled WASM solver binaries and JavaScript host. Native C++ source is intentionally not included in this distribution.
  • The standard renderer exports positions and packed color, rigid geometry, level sets, blocks and statistics. It does not expose a general writable per-particle state buffer for arbitrary velocity, mass or deformation-gradient edits.
  • The main-thread fallback is compatible but is not a performance substitute for a dedicated worker on large scenes.
  • Inline code and imported modules are trusted executable code. Worker isolation is an execution boundary, not a security sandbox.
  • Custom 3D polygon level sets are not supported by the current level-set API.

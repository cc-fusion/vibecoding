Getting Started

From zero to a running physics world in three steps.

Matter.js is a 2D rigid-body physics engine for the web. It is dependency-free, runs in the browser (and in Node), and exposes everything through a single global Matter namespace when loaded via a script tag.

1. Include the library

<!-- CDN -->
<script src="https://cdnjs.cloudflare.com/ajax/libs/matter-js/0.19.0/matter.min.js"></script>

<!-- npm -->
npm install matter-js

2. Minimal example

const { Engine, Render, Runner, Bodies, Composite } = Matter;

// 1. create the engine (owns gravity, solver, pairs, detector)
const engine = Engine.create();

// 2. create a renderer attached to a canvas
const render = Render.create({
  element: document.body,
  engine: engine,
  options: { width: 800, height: 600, wireframes: false }
});

// 3. add bodies to the world and start the loop
const ground = Bodies.rectangle(400, 610, 810, 60, { isStatic: true });
const ball   = Bodies.circle(400, 100, 30, { restitution: 0.9 });
Composite.add(engine.world, [ground, ball]);

Render.run(render);
Runner.run(Runner.create(), engine);

3. The Matter namespace

Every module is a property of the global Matter object: Matter.Engine, Matter.Bodies, Matter.Render, and so on. Destructure what you need and you are ready to go. The full module list is documented in the reference below.

Architecture

What happens on every tick of the simulation.

A Matter simulation is a loop. The Runner drives it, the Engine coordinates each step, and the Render draws the result. Understanding the pipeline makes every other module easier to reason about.

Runner.runrequestAnimationFrame loop
→
Engine.updatecoordinates the tick
→
Detectorbroad-phase: Grid buckets
→
Collisionnarrow-phase SAT tests
→
Pairstrack collision pairs
→
Resolversolve position & velocity
→
Body.updateintegrate motion
→
Render.worlddraw to canvas

Runner owns the game loop and calls Engine.update each frame. Engine.update runs the broad-phase (Detector with a Grid), the narrow-phase (Collision), updates the Pairs manager, runs the Resolver to push bodies apart and exchange momentum, integrates each Body, and finally lets Sleeping do its work. Render then draws the world — it is completely optional and independent of the simulation.

Events Reference

Every event you can subscribe to, and what you get in the callback.

Use Events.on(object, 'eventName', callback) to subscribe. The callback receives an event object whose shape depends on the source. Collision events carry a pairs array; each pair has bodyA, bodyB and a collision with depth, normal and supports.

beforeUpdateEngine{ timestamp }Before each engine step
afterUpdateEngine{ timestamp }After each engine step
collisionStartEngine{ pairs }Two bodies begin touching
collisionActiveEngine{ pairs }Bodies remain in contact
collisionEndEngine{ pairs }Bodies stop touching
beforeRenderRender{ timestamp }Before the canvas is drawn
afterRenderRender{ timestamp }After the canvas is drawn

enddragMouseConstraint{ body, mouse }User releases a body

constraintAdded / constraintRemovedComposite{ object }A constraint is added / removed
compositeAdded / compositeRemovedComposite{ object }A sub-composite is added / removed

Reading a collision event

Matter.Events.on(engine, 'collisionStart', (event) => {
  event.pairs.forEach((pair) => {
    // pair.bodyA / pair.bodyB — the two bodies
    // pair.collision.depth   — penetration depth
    // pair.collision.normal  — collision normal { x, y }
    // pair.collision.supports — contact points
    console.log(pair.bodyA.label, 'hit', pair.bodyB.label);
  });
});

Best Practices

Performance and stability tips for real projects.

  • Use a fixed timestep. Set Runner.create({ isFixed: true }) or call Engine.update(engine, 1000/60) yourself for deterministic, stable simulations.
  • Enable sleeping for big scenes. Engine.create({ enableSleeping: true }) skips idle bodies and can cut CPU usage dramatically.
  • Use collision filters. Split bodies into collisionFilter.category bitmasks and control who collides with whom via mask — fewer pairs means a faster broad-phase.
  • Prefer circles and simple polygons. Vertex-heavy bodies slow the narrow-phase. Use Bodies.circle where possible.
  • Use sensors for trigger zones. A body with isSensor: true reports collisions but exerts no physical force.
  • Remove what you no longer need. Composite.remove(world, body) keeps the world clean and the broad-phase fast.
  • Never mutate body state directly. Use Body.setPosition, Body.setVelocity, Body.applyForce etc. so internal caches stay consistent.
  • Debug with wireframes. Render.create({ options: { wireframes: true } }) is the fastest way to see what the engine sees.
